# Mamar Booking

Mamar Booking is one booking platform that every Mamar client plugs into. All of it lives in this repo, so it deploys to **mamar.site** with your normal `git push`.

| Page | URL | Who uses it |
|---|---|---|
| Setup configurator | `mamar.site/start/` | Businesses pricing their system (your page; Arabic first) |
| Booking flow | `mamar.site/b/<name>` and the overlay from `book/embed.js` | Their customers |
| Owner dashboard | `mamar.site/manage/` | Business owners (they add it to the home screen) |
| Admin | `mamar.site/admin/` | You: requests, businesses, prices, notifications |

The pages are static files on GitHub Pages. The data (bookings, prices, logins) lives in **one free Supabase project** that every business shares. Each business is walled off from the others by the database.

## Running it on this computer (no accounts needed)

```bash
cd mamar/dev
npm install
npm start
```

Open **http://localhost:5600**:

- **The database:** real Postgres running inside Node (PGlite), using the same SQL files as Supabase. Its data lives in `%LOCALAPPDATA%\mamar-pglite`, outside OneDrive on purpose.
- **Logins:** the local test logins are in `dev/seed-users.json`. They are for this computer only.
- **Notifications:** they really push to your browser. Each email is written to `%LOCALAPPDATA%\mamar-pglite\outbox`.
- **Payments:** a clearly labelled **demo payment** sheet stands in for Moyasar.
- **Tests:** run `npm test` in `mamar/dev`. They cover double bookings, capacity, prayer pauses, payments and owner isolation.
- **Fresh start:** stop the server and delete `%LOCALAPPDATA%\mamar-pglite\db`.

## Going live

You only do this once.

1. **Create the project.** Go to supabase.com → New project. Pick the region **eu-central-1 (Frankfurt)**, the closest to Jeddah. Save the database password somewhere safe.

2. **Create the database.** Open **SQL Editor**, paste **`platform/supabase/all.sql`** and run it. It holds everything, in order:
   1. `migrations/001_core.sql` → `005_config.sql`
   2. `999_grants.sql` (always last)
   3. `supabase_only.sql`

   `all.sql` is generated by `node dev/scripts/bundle-sql.mjs`, so edit the source files, not it. Optional, for the demo sites: also run `platform/supabase/seed/demo.sql`.

3. **Make yourself admin.**
   1. In **Authentication → Users → Add user**, create your login with **Auto Confirm** ticked.
   2. In the SQL Editor, run:
      ```sql
      insert into public.admins (user_id) select id from auth.users where email = 'YOUR EMAIL';
      ```

4. **Connect the site.** In **Project Settings → API**, copy the *Project URL* and the *anon public* key into `platform/config.js` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`). The anon key is public by design. The **service_role** key must never go in the repo.

5. **Set up notifications.**
   1. Run `npx web-push generate-vapid-keys` once.
   2. Put the **public** key in `platform/config.js` → `VAPID_PUBLIC_KEY`.
   3. In **Edge Functions → Deploy a new function → Via editor**, name it `notify` and paste `platform/supabase/functions/notify/index.ts`.
   4. Add these secrets:
      - `VAPID_PUBLIC_KEY` and `VAPID_PRIVATE_KEY`
      - `WEBHOOK_SECRET` (any long random text)
      - optional: `RESEND_API_KEY` and `NOTIFY_EMAIL` (a free resend.com account sends the emails)
   5. Add a webhook in **Database → Webhooks → Create**:
      - Table: `notifications`
      - Event: Insert
      - Type: Supabase Edge Function → `notify`
      - Header: `x-webhook-secret: <the same random text>`

6. **Turn on payments** (only for businesses that buy deposits or prepayment). Deploy a second function named `moyasar` from `platform/supabase/functions/moyasar/index.ts`. Each business needs **its own** Moyasar account. In the admin, open the business → Payments, then paste its `pk_…` and `sk_…`. The secret key is stored server-side only. Test with Moyasar's test keys first, then make one real small payment before going live.

7. **Publish booking links.** Create a fine-grained GitHub token:
   - GitHub → Settings → Developer settings → Fine-grained tokens
   - Repository access: **only** `ahmedps520-svg/mamar`
   - Permissions: **Contents: Read and write**

   Paste it in the admin's Settings. It stays in your browser only. Booking links already work without it; the token only adds the page that gives WhatsApp and Instagram previews the business's name.

8. **Install the admin on your phone.**
   1. Open `mamar.site/admin/`.
   2. On iPhone, tap Share → **Add to Home Screen** (iOS 16.4 or newer). Android is the same idea.
   3. Open it from the icon and turn on notifications.
   4. Press "Send a test notification".

9. **Push to GitHub.** That's it.

## Day-to-day

- **New request:** your phone buzzes, plus an email and a live card in the admin.
  1. Open it.
  2. Press **Create business**.
  3. Create the owner's login in Supabase (Authentication → Add user), then attach it in the admin.
  4. Send them the details yourself.
- **Paid:** set the business to **Active**. Its link `mamar.site/b/<name>` works immediately. Give them the one-line embed code shown in the admin.
- **A client who can't do the questions themselves:** use **New system for a client** in the admin. You fill in the same flow for them.

## Running costs

- **Free tier limits:** the free Supabase tier pauses after about 7 days without any activity and keeps no backups. Once the first client pays, move to **Pro** ($25 a month); the care plans cover it.
- **Supabase changes:** projects created since mid-2026 need explicit grants. `999_grants.sql` handles that; run it again whenever you add a function.
